## 同源维护

以完整Markdown正文作为本目录文档源；modules.json是40模块结构化契约，修改模块必须同步正文和结构化源。脚本不会调用旧V1.0生成器重放旧规则。图片中12张开户/关系图使用当前绘图源，其余12张为已核对未受影响的保留PNG。

使用本机可用Python并安装scripts/requirements.txt中依赖后：

    python scripts/draw_figures.py
    python scripts/build_prd.py --pdf
    python scripts/check_prd.py 本目录绝对路径
    python scripts/package_prd.py

本轮采用文件生成PDF，无浏览器自动化。Word结构/图片尺寸及PDF文字读回不等同Word分页实测、生产或UI集成验证。

本次追加修复已写入现行正文：选择客户后，空搜索立即完整展示本客户已关联主体，不截断10条；可按名称/信用代码筛选。当前客户无匹配时显示明确空态，全局已有未关联主体另列，只有用户选择才关联复用；空搜索也可进入新增，保存前查重未命中才新建。选主体后唯一店铺自动展示复用，无店同页新增，历史多店保留待核对且不自动选第一店。更换客户清空主体/店铺及派生资料、更换主体重新加载下游，同时解除本申请旧附件关联并提示，已提交历史快照保留。相关详设见M02/M03/M06、图4-5/4-6、UI12-10至UI12-13。

本轮V1.3：新申请逐行保存结果后仍须被指派媒介显式点击“完成本次开户”；历史已完成保留。开户待办按一申请汇总并区分成功/待办理/异常/纵横待补，退出可回原单继续；已办和资料待补保留原单入口。只有主管派单，普通媒介仅办理本人当前任务。后台行业字典可搜选和增改启停。主体/店铺/直客普通维护的流转备注选填，不以licenseEvidence或备注拦身份字段；系统审计保留。开户只选择供应商并只读引用，不填供应商银行；独立供应商主档保留旧多收款账户关系，地址未核实为旧独立字段。用户页使用明确业务标签并清理开发评审话术。

收尾细则：全部行成功或明确已取消后可显式完成，全取消显示已取消；失败需重办或明确取消，未知/待同步不得取消绕过。完成按钮后才进入模板后置审批，显示“开户已完成，流程待复核”。原单办理明细置顶，材料及历史折叠；“保存办理进度”保留pendingValues未提交输入，不冒充成功结果。

状态文案统一为“待确认完成”。重复完成保持既有结果，可提示已完成，不新增账户或外部执行。显式完成后，无后置节点才进入最终已办；有后置节点先显示“开户已完成，流程待复核”，后置完成后终结，全取消最终为已取消。

V1.4批量开户：媒介在原申请内使用可编辑表格和Tab连续录入，供应商可搜索选择并批量应用到选中可编辑行，默认只填空值，覆盖已有值必须显式操作；整表保存草稿允许空账户ID；选中行一次登记成功，全部校验通过才整批保存，有错不写入本批成功结果并按行按字段提示，同批重复双边标注。成功/未知/待同步/已取消行不参与批改，异常继续单行办理；名称和纵横选填，原申请数量、行ID、关系、归属及历史快照保持，系统管理员按既有授权可代办，其他业务角色只读；完成本次开户独立。V1.4当时未含Excel粘贴，本轮V1.5已增加TSV预览填表，仍不提供xlsx上传。
