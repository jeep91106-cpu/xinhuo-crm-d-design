## 1. 规则替代清单

| 原文或旧实现 | 当前生效规则 | 影响 |
| --- | --- | --- |
| 本地推执行前强制有来客 | 来客名称 / ID 均非必填，缺失不阻断开户完成 | 删除原型硬门槛；基础身份校验仍执行 |
| 来客只在媒介档案页编辑 | 商务在申请第2步维护；媒介在原申请页补全和编辑 | 不跳离原申请，不丢上下文 |
| 直客仅有演示候选且只能绑第一行 | 商务按行查询 / 有据录入，媒介可补；成功后有据更正 | 查不到不虚构结果，仍可留空或人工录入 |
| 客户下整棵树决定业务归属 | 主体、店铺为公共引用，账户保存业务商务责任 | 补资料人不自动取得账户归属 |
| 主菜单与子菜单都像功能按钮 | 栏目为不可点击标题；功能页为缩进按钮 | 栏目不因业务操作自动折叠；唯一当前功能 |
| 提交 / 补资料后跨菜单跳转 | 事务成功留在原模块的原单；显式跨模块操作才导航 | 返回来源、原筛选、未保存保护 |
| 所有缺口都归为未来列表配置 | 本地列序、列宽、显隐、密度、排序和分页偏好已实现 | 不改变数据权限，跨设备同步仍属生产实现 |

授信状态和其他既有业务决策按其最新确认记录执行；商务个人额度维持已取消。本轮不重新裁定授信政策。本轮不通过界面调整偷偷修改计价、返点、钱包归属或生产迁移规则。

## 2. 关键对象与字段位置

| 对象 | 字段 | 填写者与时点 | 保存、查重及回显 |
| --- | --- | --- | --- |
| 公共主体 | 名称、统一社会信用代码、行业、主体开户行、银行账号、住所、联系人、电话、证照名称 / 来源 | 商务第2步建档；授权媒介可在原单补全 | 代码按字符串规范化查重；命中复用；更正留前后值、理由、操作人和版本 |
| 公共店铺 | 名称、经营地址、来客名称 / ID | 商务第2步；媒介原单 | 本地推适用；一个当前来客；缺失可完成；相同来客跨CRM店铺提示核对，不自动合并 |
| 申请行 / 账户 | 直客名称 / ID、来源、依据 | 商务第3步按行；媒介办理时；成功后独立更正 | 非空直客一对一、有效在途查重；历史成功事实不覆盖 |
| 申请 | 客户、产品、主体、店铺、区域、负责商务、实际提交人、办理路径、对象类型、渠道关系、材料、流程和表单版本 | 商务提交时 | 每条拟账户独立行；共享公共资料不等于共享归属或资金 |
| 供应商 | 代理名称、代理ID、平台范围、银行账号、开户行和支行地址 | 授权媒介 | 与主体银行字段分开；逐版本留痕；媒介逐行选最终供应商 |
| 账户结果 | 最终名称、广告账户ID、纵横ID | 开户媒介 | 名称和账户ID为完成基本条件；ID重复拦截；纵横可后补 |

号码作为字符串保存，不用固定编号数量或统一号长推断真实平台身份。历史没有的数据保持未知；本地补录标明为演示更正。

## 3. 三个资料时点不能混用

1. **当前公共资料**用于下次办理和展示当前事实。
2. **申请提交快照**保存当时主体、店铺、逐行直客、意向供应商、责任和配置版本。旧单没有快照时明确未保存，不事后拼接成“原始资料”。
3. **执行快照及外部结果**保存实际使用的主体、来客、直客、最终供应商和请求身份。结果未知、外部成功待同步时锁定原请求，不能换账号重试。

成功后补直客或纵横属于有据更正；原外部结果不被重写。一个店铺当前来客发生变化，界面同时展示申请时值和当前值，不能让旧申请看起来像从一开始就使用新值。

## 4. 通用交互验收

- 栏目标题与功能页具有不同视觉、语义和点击行为；40个模块各有唯一归属栏目。
- 新增、补资料、提交、详情与返回形成连续路径，侧栏选中的是当前业务功能。表格行内按钮不再次触发行点击，避免双重跳转。
- 有未保存输入时，离开、浏览器后退、弹窗关闭均提供保留或放弃选择；取消离开不篡改浏览器历史；成功保存不会误报丢失输入。
- 账户筛选按当前评审身份恢复；表格的显隐、列序、列宽、密度、排序与分页偏好保存到本机浏览器，身份列和操作列保持可见。
- 表格仍为日常数据主视图；卡片仅用于摘要、分组和关系说明，不能用卡片隐藏完整账户明细。

## 6. 必须保留的边界

原型使用历史真实客户、主体、店铺和账户样本；新增业务、金额、人员及操作均为本地演示。银行付款、企业微信审批回调、媒体开户接口、生产附件、服务端鉴权、跨人并发事务、完整历史迁移和所有旧计价分支不因本轮UI修订而变成已实现。

扩展字段可编辑类型、选项、可见性和必填，当前支持商务申请阶段；页面展示默认录入角色，暂不提供字段采集角色编辑；额外流程节点按版本生效。配置不能绕过非空ID唯一约束、外部结果锁定或真实资金记账约束。正式上线另按原PRD的迁移、回滚及验收要求实施。
