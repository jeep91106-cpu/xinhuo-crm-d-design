## 已确认的当前规则

| 对象/操作 | 当前规则 | 替代的旧要求 |
| --- | --- | --- |
| 客户与主体 | 客户1:N主体；客户名称自定义，先搜索查重再选择或新增 | 不把客户名称当主体法律名称 |
| 主体与店铺 | 主体当前1:1店铺；店铺名称自定义真实店名 | 新建不再按主体多店模式操作 |
| 主体与直客 | 主体当前1:1直客；直客名称=主体填写公司名称=营业执照主体名；直客ID可空 | 废止直客与广告账户1:1、按申请行直客占用及逐行直客编辑 |
| 店铺与来客 | 店铺名称即来客名称，只填写一次；来客ID可空 | 不再提供独立来客名称输入 |
| 主体与账户 | 同主体可有多个广告账户，共享主体直客和店铺来客 | 不因共享直客拦截同主体另一账户 |
| 账户名称与ID | 账户名称自定义非必填；广告账户ID在完成时必填防重；纵横可后补，非空一对一 | 废止账户名称作为成功必填 |
| 商务开户 | 原前三步合并同页；输入搜索查重客户，主体店铺原地维护，上传营业执照及资质 | 不再要求按四步切换或逐行填写拟账户/供应商/直客 |
| 开户数量 | 商务只用减号、数字、加号确定数量 | 逐行操作移交媒介，不取消内部行级办理事实 |
| 媒介办理 | 看到申请数量和逐行账户名称、供应商、账户ID、纵横及结果 | 主体直客从主体引用，不按行独立编辑 |
| 资料维护 | 商务优先填，媒介可在原申请新增/补全/更正主体店铺与其ID | 当前资料不覆盖提交或执行快照，不改变商务归属 |
| 材料配置 | 产品与材料类型可配置显示、可选、申请必需、执行前补齐；默认营业执照和其他资质可选 | 不擅自把全产品营业执照或任意材料设为强制默认 |
| 文件保存 | 本地IndexedDB保存真实选中文件，元数据按原单快照，可预览和下载 | 仅文件名或备注不算上传；不宣称已上传生产存储 |
| 历史兼容 | 存量同主体多店等保留原行与原值，标历史关系待核对 | 不自动合并、删除或编造已迁移 |

## 附件配置与数据契约

流程版本内的`attachmentPolicies`为数组，每项包含`id`、`label`、`product`（全部产品或指定产品）、`visible`、`required`、`requiredAt`（`submit`或`execution`）、`accept`和`maxSizeMB`。当前演示允许PDF、PNG、JPG/JPEG、WEBP，大小上限10MB；这是可配置演示参数，不推定为未经发布的公司制度。默认`license`（营业执照）与`qualification`（其他资质）均可选。

申请附件元数据为`{id,name,type,size,policyId,subjectId,storageKey,storedLocally:true,uploadedAt}`；真实文件内容存在本地IndexedDB，`storageKey`用于读取预览/下载。显示规则来自单据绑定的流程版本；材料类型与产品共同匹配。媒介在原单补上传满足执行阶段要求。未知、外部已成功待同步的原请求必须继续核实或补同步，不因后来新增材料要求发起第二次外部执行。

上传前必须先选择主体；切换主体时解除本申请原附件关联并提示重新选择，不能把旧主体文件默用作新主体资质。提交及新的外部执行前拦截跨主体附件；历史已提交/执行文件快照保留。
