# 原型与 PRD 审查对照

原审查保留 V1.0 文档、来源及图示作为可追溯基线。此表说明哪些建议已经在交互原型体现，不能代替业务会签或正式 PRD 多格式修订。

| 审查项 | 原型中的处理 | 后续边界 |
| --- | --- | --- |
| A01 公共引用与客户业务范围 | M02 本客户业务、共享核对、在途申请、数据结构分开；按稳定账户客户关系归集 | 多客户业务引用的主展示关系仍须在正式数据契约中确认 |
| A02 缺完整客户工作区 | 独立客户全景、主体店铺定位、展开式完整关系图、账户详情与继续开户 | 关系图为本轮补充的交互方案，等待产品评审 |
| A03 供应商职责 | 商务可预选可空，媒介按行确认；成功/未知/待同步行不能改供应商 | 生产供应商能力、资料模板与路由待联调 |
| A04 非本地推资料层 | 先选产品；非本地推显示业务档案，保留旧 shop 层引用；不展示来客与直客输入 | 具体产品和供应商的开户必填清单需逐一接入 |
| A05 当前资料与历史事实 | 申请时快照、当前店铺来客分别展示；已成功结果身份锁定 | 历史缺快照的旧单标未留存，不倒填推测值 |
| A06 旧来源商务额度冲突 | 总账明确无商务个人额度；账单与实际操作留痕继续保留 | R06 早期段落不能覆盖后续取消决定 |
| A07 历史客户重名 | 新建按规范化名称拦截；迁移模块提供保留来源、冲突待处理机制 | 不擅自把同名历史客户资金合并，尚未迁移生产 |
| A08 账户结算方语义 | 每笔资金业务明确资金方；账户详情不展示虚构的永久资金钱包 | 报表口径按业务事实关联与去重 |
| A09 平台转户同商务 | 两端同结算范围、同已知商务；未知归属不作相等 | 已覆盖模型测试；真实平台转户未调用 |
| A10 查询与路由 | 支持客户/主体/店铺/账户检索与带上下文开户；直客 CRM 未查到与平台未接入有明确区别 | 平台实际查询、无权限、网络失败状态待真实接入 |
| A11 权限分层 | 查看资料、办理动作和薪资可见性分别处理；多角色入口、角色配置可评审 | 浏览器角色模拟不是生产 RBAC，也不是后端字段鉴权 |
| A12 新建与关联、草稿与批量 | 关联已有资料、上下文新增、显式恢复草稿、分页选中、交接协办 | 多浏览器并发和后端事务待正式实现 |

已确认的关系基线为：一店当前一个来客、来客可关联多账户，非空直客与纵横各自与账户一对一。主体允许多个店铺及多个直客所对应的账户。不能再把来客视为主体单字段，不能把直客放到来客下面维护一个共享池。

原型选用了真实数据库资料名称与完整字符串 ID。真正没有证据的直客、纵横、账户商务为空，不用任意名称或旧客户销售字段拼出“真实归属”。演示新户以 DEMO 前缀标明。

财务闭环示例以本地模型与回归测试为依据，保留资金来源、单据状态、计价快照、原请求、冻结、一次记账和对账分层。正式系统仍须实现数据库事务、幂等约束、权限及外部回调验证。
