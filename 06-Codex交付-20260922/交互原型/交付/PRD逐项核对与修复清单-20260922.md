# PRD 与交互原型核对记录 · 2026-09-22

## 阅读结论

本轮按“字段能否在正确角色、正确节点录入 → 是否保存 → 是否在详情回显 → 是否校验关系与权限 → 异常如何恢复”核对，不能把页面中出现了字段名算作交互完成。

最初发现的核心缺口包括：来客完成门槛与用户口径相反；商务在开户上下文无法补公共资料；直客不能任意行分别维护；主体资质与供应商代理银行字段缺少完整编辑链路；菜单类别和功能混淆；行按钮重复触发导航；保存后原单定位不连续。相应代码和现行操作文档已修订。

## 数据真实性与剩余范围

真实历史样本为14客户、69主体、186店铺或业务档案、215账户、7供应商；只显示已互证的来客。新增测试数据名称带“演示”或“验收”，不会补造成真实数据库内容。资料维护产生本地更正版本，不写回生产。

本轮交付是可交互评审原型和修订文档。40模块页面检查通过，不等于已实现全部后端功能、所有字段权限组合或完成生产验收。每份逐项记录最后一列都列出没有接入的真实接口和历史规则，尤其是银行/企微/媒体、后台鉴权、全部旧财务分支和全量迁移。那些项目不被一概标为“已完成”。

## 独立复核与整合

核心字段、财务字段、运营字段分别在独立工作树实现，由根任务整合和浏览器验收。独立复核发现并修复：历史后退覆盖、底部退出绕过、嵌套弹窗误报、身份视图串用、草稿审计旧角色闭包、内置配置类型冲突、财务重复关闭确认、导入与附件草稿脏状态互相清除。最终提交和检查结果见交付时的 Git 记录与 `qa/validation-summary.json`。
