## 从哪里开始评审

新增开户按 [开户演示操作指南](交付/开户演示操作指南.md) 逐角色操作。2026-09-22当前规则为V1.2：商务前三步合并一页，仅选数量；主体一店一份直客，同主体账户共享直客，名称联动而ID可空。媒介原单补资料并逐行办理。当前规则追溯见 [本轮修订记录](交付/PRD修订补充-V1.2-20260922.md)。本轮实现和浏览器验证由协调者记录，旧版通过记录不能代替。

1. **客户完整关系**：工作台 → 打开允城全景 → 左侧选择“西安市未央区潮拍摄影店（个体工商户）”。“本客户业务”默认表格显示四个真实账户；“数据结构”展示可展开的客户→主体→店铺→账户关系图。浏览器内新增过演示账户后，数量会增加并标明演示。
2. **完整开户**：工作台→新增开户，同页搜索客户选择/新增、维护主体唯一店铺、选择资质文件并用“− 数字 +”确定开户数量；媒介主管派单后，媒介按数量逐行选择供应商、填写唯一账户ID，账户名称可空、纵横可补。结果支持成功、明确失败、未知核实和待同步。
3. **查重与异常**：用已有账户 1873296142902524 回填将被拦截。未知结果须核实，确认未发生要填依据；待同步锁定原账户身份。成功后可以到账户详情补纵横，归属不随经办者改变。
4. **资金闭环**：到账与认领 → 载入资金演示场景 → 登记收款 → 财务确认 → 拆分认领。进入充值办理，分别演示主管派单、财务前返、冻结、未知核实、成功待同步、一次入账，再到总账和对账核对。
5. **后台配置**：切换系统管理员 → 表单与工作流。可添加扩展字段、设置必填、在核心节点之间插入步骤，按产品/区域发布版本。旧申请保留旧版本；新申请按范围优先级选择配置。
6. **其他模块**：人事行政、收益、消耗、合同、开票、迁移、审计等页面可载入合成演示样例、新建、检索、查看详情和进行模块对应状态流转。工资及核算页面要求相应角色，数据不是实际员工工资。

## 页面与数据关系约定

日常处理以**一账户一行的表格**为主，支持搜索、筛选、分页、批量选择和详情。分组卡片用于工作台指标、详情分组和关系图，不替代账户明细表。

- 客户、主体、店铺是可复用公共资料；“本客户业务”与“共享关系核对”分开查询。
- 客户1:N主体，保留既有公共主体共享引用；主体当前1:1店铺、1:1直客。同主体多个账户共享主体直客，直客ID可空，直客名称即营业执照公司名。
- 店铺名自定义真实店名，来客名称直接使用店铺名，不双填；来客ID可空。账户名称可空，账户ID完成必填防重；纵横可后补，非空与账户一对一。
- 商务优先填写，媒介原单补全和更正；历史主体多店保留来源并标待核对，不自动合并或改写。
- 申请保存客户上下文、拟归属商务、实际提交者及办理版本；成功账户继承申请责任。
- 每笔资金业务独立关联结算方，不沿公共资料关系树累加资金，不存在商务个人用款额度。
- 非本地推保留旧系统对应的“业务档案”关联，不强制当作实体门店，不把 WZ/DY/OM 等旧号当来客。

## 真实数据和演示数据

真实样本共 **14 个客户、69 个主体、186 个店铺或业务档案、215 个广告账户、7 个供应商**。来自既有只读查询归档及数据库备份，本轮未重新查询生产。只有 6 个店铺显示已经互证的来客。

未取得可靠来源的账户商务、直客、纵横保留未知。未复制真实余额、银行资料、电话、工资或平台凭据。财务期初、申请金额、员工与新办账户均为明确标注的本地演示。修改真实样本时叠加“本地更正”标识，不声称改了生产。

所有操作仅保存在当前浏览器本地。不同浏览器或不同来源地址各自独立；不要把本地存储当多人协作数据库。右上角“恢复演示数据”可重新开始，会清除当前原型演示操作。

## 实际边界

这是交互评审原型，不是可投产系统。角色切换用于评审；后台真实鉴权、完整RBAC执行、并发数据库事务、银行/企微/媒体回调、生产附件存储、人员同步未接入。本轮附件采用当前浏览器本地IndexedDB保存真实文件并预览，不宣称远端上传；按产品与材料类型配置可选/申请必需/执行前补齐，默认营业执照及其他资质可选。财务模板候选参数不隐式改变入账。

原型金额计算覆盖验证记录所列本地场景。旧供应商全部计价分支、三位小数广告币、跨产品币种转换和完整生产历史迁移没有在此模拟，应按旧接口及生产数据另做实现验收。导入页面演示预检和状态，不等同于生产 Excel ETL。

列表已支持列显隐、顺序、列宽、密度、排序、分页和个人视图保存。栏目标题与功能按钮明确区分；提交留在原业务模块，未保存离开有提示，可以返回来源及账户筛选。配置保存在当前浏览器，生产跨设备偏好同步尚未接入。

用户要求直接修改原PRD与原原型。原PRD目录继续使用“薪火CRM-完整PRD-V1.0.md/html/docx/pdf”原文件名，正文内部注明2026-09-22当前修订V1.2；关系、字段、流程、图和验收直接更新，不只靠补充文档。工作树中的交付/PRD-V1.2仅为协调者覆盖原入口的隔离产物，回退备份不是新的用户阅读入口。
