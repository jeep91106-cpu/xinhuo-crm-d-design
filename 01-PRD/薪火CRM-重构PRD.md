## 1. 背景与问题

薪火是广告流量代理。上游以巨量引擎为主，公司帮两类合作方开广告账户、垫款充值、代运营：

- **客户**（付钱、拿返点、用授信）可以是广告主本人，也可以是同行渠道。  
- **直客**在本产品里**不是一种客户**，只是巨量给营业执照公司发的客户编号（直客 ID）。一家主体可以有多个直客 ID。

现网是 RuoYi-Vue 3.8.2，2026-07-06 上线。商务、媒介、财务、老板同时反馈不好用。实测对应四件事：

| 反馈 | 现网证据 |
|---|---|
| 字段过多 | 客户表 72 列，31 列全空；开户申请除客户外主体/店铺/供应商全是自由文本 |
| 流转不能回填、选择 | 申请单不关联已建主体/店铺；自有端口回复不建账户，媒介再录一遍账户 ID；每笔充值强制手填前返/后返 |
| 无工作台 | 无角色首页；待办在 `dig_customer_expand` 计数，没有可视化 |
| 无后台模板 | 字段和审批人写死在代码 / 菜单树 / `base_approval_process` 金额区间，不能按组织配流转 |

使用现实：纯商务 14 人里 12 人零登录；开户/充值由 5+2 名媒介和 1 名 AE 扛；充值/转户/退币 80%–100% 走微信机器人。财务现金收款 142/145 停在待确认。系统对商务几乎只有「提开户申请」一个价值，还要手抄。

## 2. 目标与非目标

### 2.1 目标（按优先级）

1. **商务一次填对**：按业务类型只出该出的字段；主体、店铺、供应商从已有记录选择。  
2. **整单流转可回填**：下游看到上游已填内容；媒介可改正来客 ID，改动留痕并通知商务。  
3. **角色工作台**：商务 / 开户媒介 / 充值媒介 / 财务 / 老板各一个队列页，只放自己要处理的事。  
4. **后台可配**：字段模板 + 工作流（企业微信组织，主链商务 → 开户媒介 → 充值媒介 → 财务）。  
5. **合并双树**：抖音事业部与其他媒体合成一套，用「媒体产品 + 供应商类型」区分，不再用两套菜单决定客户 `types`。

### 2.2 非目标

- 不重做 客户 → 主体 → 店铺 → 广告账户 四层关系。  
- 不限制一个主体只能做一种媒体产品。  
- 不删除腾讯 K4、快手、外转代理商路径。  
- 不沿用现网角色账号作为权限基线。  
- 本仓库不承载生产数据和密钥。

### 2.3 成功标准（上线后可观测）

- 商务能独立提交开户申请，不再依赖 AE 代录主体/店铺文本。  
- 开户申请到账户落库不再出现「回复一次、同步再录一次账户 ID」。  
- 现金到账、对账单能在财务工作台清掉积压（现网几乎未闭环）。  
- 沈阳发起的单不出现在厦门队列。

## 3. 用户与组织

登录身份来自**企业微信**，人属于组织节点（现网已有厦门 / 天津 / 沈阳事业部）。工作流按组织匹配处理人，不按「这个客户永远属于某个人」写死。

| 角色 | 现网人数（参考） | 重构后职责 | 工作台 |
|---|---|---|---|
| 商务 | 15（多数未用） | 建客户、补主体资质、提开户、提授信/收款 | 我的申请、驳回、改动通知 |
| 开户媒介 | 5 | 审资质、回填账户 ID / 纵横 ID、维护供应商 | 开户队列 |
| 充值媒介 | 2 | 确认充值、转户、退币、供应商余额 | 充值队列 |
| 财务 | 3（几乎未用） | 确认到账、对账、授信/退现审批 | 资金队列 |
| 老板 / 总审批 | 董事长+总经理 | 看盘、越级审批 | 只读看板 |
| 系统管理员 | — | 字段模板、工作流、组织映射 | 配置中心 |
| 机器人 | 5 服务号 | 微信群解析后写入同一套单据 | 无界面 |

一人可兼多角色（现网已有「商务+开户+充值」兼职）。工作台按**当前角色切换**，待办按角色+组织过滤。

## 4. 对象模型（保持原逻辑，只加字段）

```
供应商 ──────────────┐
客户 ── 主体 ── 店铺 ── 广告账户
 │                    │
 钱包×2 / 流水 / 对账   充值 / 消耗 / 转户 / 退币
```

| 对象 | 业务含义 | 加什么 | 不加什么 |
|---|---|---|---|
| 客户 | 合作方：付钱、返点、授信 | 无新实体 | 不把「直客」做成客户类型的替代 |
| 主体 | 营业执照公司 = 巨量资质主体 | 行业、信用代码、开户行名称/账号、住所；联系人电话可从客户带出可改 | 不把业务类型做成主体互斥枚举 |
| 店铺 | 仅本地推有意义 = 抖音来客 | 来客名称、来客 ID（19 位）正规化；非本地推可不建或自动占位 | 不强制每个账户手建同名店铺 |
| 广告账户 | 媒体投放账户 | 直客 ID、纵横 ID、账户所属（个人/渠道公司，可默认） | 业务类型仍用账户 `type` |
| 供应商 | 自有端口 AGENT 或外转 NOAGENT | 代理商 ID、开户行号码/地址 | 每开一个账户重填代理商银行信息 |
| 开户申请 | 商务 → 媒介的工单 | 外键指向客户/主体/店铺/供应商；直客 ID、来客 ID 随单走 | 主体名称等自由文本作为主数据 |

**一个主体多个直客 ID**：列表在主体页只读汇总，写入发生在开户申请和广告账户。默认理解是不同供应商/端口各发一个号；若同一端口也有多个，仍挂在账户上即可。

**媒体产品（账户 type，沿用现网字典）**

| 值 | 含义 | 端口 |
|---|---|---|
| 102 | 巨量本地推 · 自有 | API |
| 1001 | 本地推 · 外转 | 记账 |
| 100 | 巨量 AD · 自有 | API |
| 1004 | 巨量 AD · 外转 | 记账 |
| 1002 | 腾讯 K4 | 记账（8 位账户 ID，无来客/纵横） |
| 1003 | 快手 | 记账 |

## 5. 信息架构

合并后不再按「抖音事业部 / 其他媒体」分两棵树。

```
工作台（按角色默认落地）
客户（含主体、店铺、账户页签）
开户
资金（收款 / 授信 / 充值 / 转户 / 退币 / 退现）
消耗与对账
供应商
配置（字段模板 / 工作流 / 组织）  — 仅管理员
报表
```

腾讯、快手作为媒体产品出现在同一套页面，用字段模板隐藏巨量专用项。停用的历史菜单只隐藏。

## 6. 角色工作台

每条待办是一张业务单据 + 当前节点 + 到达时间 + 发起组织。点击进入原单，不是另填一张表。

### 6.1 商务

- **待我处理**：草稿、被驳回、媒介改过来客/资质需确认。  
- **进行中**：已交开户 / 授信 / 收款，看当前节点和停留时长。  
- **快捷**：新建开户、新建客户。  
- **我的客户**：最近操作的客户、授信占用、待开户主体。  
- 不放全公司消耗大表。

### 6.2 开户媒介

- 队列按工作流组织过滤。列：客户、主体、媒体产品、供应商、来客 ID、等待时长。  
- 处理页：**只读带回**商务字段；填写账户名称 / ID / 纵横 ID；可改来客（原因必填）。  
- 自有端口：回填后系统建或同步账户，禁止再要求「去另一个菜单贴同一账户 ID」。  
- 外转：回填后直接建账户，状态「待代理商线下开通」可并行。

### 6.3 充值媒介

- 待确认充值；同步失败（`sync_state`）；供应商低于阈值；外转待确认线下到账。  
- 打开充值单时前返/后返/钱包**默认带出**客户或账户值，允许改。  
- AGENT 走原 API 划款；NOAGENT 只记账。逻辑与现网一致。

### 6.4 财务

- 待确认现金到账（必须能指定一类/二类钱包，避免现网「多个钱包」报错卡死）。  
- 日对账单待确认。  
- 授信、退现按工作流进待审，禁止「254 单全部直接过」。  
- 退现现网 0 单，界面保留，节点可配。

### 6.5 老板

- 当日/当月消耗、授信占用、开户平均处理时长、各组织队列积压。  
- 不下钻改单；越级审批从待办进原单。

## 7. 核心流程

### 7.1 客户与主体建档

1. 商务建客户：名称、标签（直客/渠道、自运营/代运营）、联系人电话、返点、授信策略。  
2. 建或选择主体：公司名称。非本地推补资质七项 + 行业；本地推可后补，但开非本地推账户时再拦。  
3. 直客客户常常「客户名 = 主体名」，允许一键带出，仍是两层记录。  
4. 渠道客户下一个客户挂多个主体。

### 7.2 开户申请

1. 选客户 → 选主体（带出资质）→ 若账户类型是本地推：选或新建来客（名称 + 19 位 ID）。  
2. 选供应商、媒体产品、开户数量、类目/备注。  
3. 直客 ID：商务知道就填；可空，由媒介补。同一主体下已有直客 ID 可选择。  
4. 提交进入工作流「开户媒介」节点，按发起人组织找队列。  
5. **禁止**再校验「申请端内/端外必须等于客户 types」这种双树遗物。

### 7.3 开户处理

1. 媒介看到完整只读上下文。  
2. 回填每个账户：名称、账户 ID、纵横 ID（腾讯/快手隐藏纵横）。  
3. 改来客 ID：原因、改前改后、通知发起商务。  
4. 提交：  
   - 外转：创建广告账户（现网已有）。  
   - 自有：创建或按 ID 拉取并**绑定本申请单**，不再让人去「同步抖音账户」重录。  
5. 节点到「完成」或进入充值（若申请时勾了首充）。

### 7.4 资金与充值（保持原资金模型）

三种钱不变：现金备款、授信、账户货币。换算仍是：

`货币 = 现金 × (1 + 前返)`，后返事后结算。

1. 商务或机器人发起充值：选账户，金额，钱包；返点默认带出。  
2. 系统拆授信/现金（现网约 96% 授信）。  
3. 工作流到充值媒介确认 → AGENT 调 API / NOAGENT 记账。  
4. 转户、退币保持现网规则，入口收进充值媒介工作台，逐步替代纯微信操作。

### 7.5 消耗与对账

- 自有：定时拉巨量消耗。  
- 外转：导入，账户 ID 必须已存在。  
- 日对账单进财务工作台，完成态必须有人点确认。

## 8. 字段与模板

字段分三层：**对象主数据**（长期） / **申请单快照**（当次） / **模板开关**（显隐必填）。

### 8.1 商务 · 本地推

| 字段 | 层 | 规则 |
|---|---|---|
| 直客名称 | 主体名 | 必填，可选择已有主体 |
| 直客 ID | 申请单 → 账户 | 选已有或手填；一主体多值 |
| 来客名称 | 店铺 | 必填 |
| 来客 ID | 店铺 | 19 位数字必填 |

### 8.2 商务 · 非本地推

| 字段 | 层 | 规则 |
|---|---|---|
| 行业 | 主体 | 必填 |
| 公司名称 | 主体 | 必填 |
| 社会信用代码 | 主体 | 18 位 |
| 开户银行名称 / 账号 | 主体 | 必填 |
| 住所 | 主体 | 必填 |
| 联系人 / 电话 | 主体，默认可带客户 | 必填 |

腾讯：无直客 ID / 来客 / 纵横。快手同理按模板关。

### 8.3 开户媒介

| 字段 | 层 | 规则 |
|---|---|---|
| 广告账户名称 / ID | 账户 | 必填；巨量 16 位，腾讯 8 位 |
| 纵横 ID | 账户 | 巨量必填（模板） |
| 供应商 | 账户引用 | 选择 |
| 账户所属 | 账户 | 默认：客户标签渠道 → 渠道公司，否则商务个人；可改 |
| 代理商名称 / ID / 开户行 | 供应商 | 账户页只读引用，去供应商档案维护 |

### 8.4 模板配置（管理员）

维度：媒体产品 × 单据类型（开户申请、开户回复、充值）。  
每字段：显示 / 必填 / 只读 / 默认来源（客户、主体、账户、空）。  
发版不改代码即可加减「来客 ID」这类规则。

## 9. 工作流

### 9.1 主链

`商务提交 → 开户媒介 → （可选）充值媒介 → （资金类）财务 → 结束`

可在节点间加「部门经理」「城市负责人」。颗粒度：人 / 角色 / 部门 / 部门负责人 / 发起人同组织。

### 9.2 组织

企业微信部门对齐 CRM 组织。规则示例：「发起人属于沈阳* → 开户媒介候选人 = 沈阳媒介部角色」。厦门、天津同理。无匹配则升到上级或管理员兜底（可配）。

### 9.3 实例数据

每步记录：节点、处理人、到达/完成时间、意见、字段变更。提成与时效报表从实例取，不从客户 `sale_id` 猜。

现网 `sale_id` 只表示「谁录的」，6/9 渠道客户挂在管理员下，**不再当归属真相**。

## 10. 权限与数据范围

- 功能权：角色 × 菜单 / 按钮。  
- 数据权：工作流候选人 + 「我发起的」+ 管理员配置的组织范围。商务默认看自己发起及被加签的客户。  
- 媒介默认看本组织队列，不默认全库（现网开户媒介 data_scope=全部，是代录造成的）。  
- 外部渠道自助登录（现网空角色）本版本不做。

## 11. 对现网逻辑的复用与修补

必须保持：

- 四层对象、三种资金、前返后返公式、AGENT/NOAGENT 分叉、外转消耗导入、授信占用。  

必须修：

- 双入口导致同一公司建两套客户（54 例）。  
- 开户申请自由文本、自有端口不落账户。  
- 充值返点每笔必填。  
- 现金收款多钱包报错导致 142 单悬挂。  
- 授信申请全部自动通过。  
- 店铺编号被当成内部流水（DY/OM/WZ-），来客 ID 只有开户申请 141/190 张在用且未正规化。

## 12. 非功能

- 消耗/充值按 `account_id` 关联必须建索引（现网无索引，报表会扫百万行）。  
- 生产禁止事务性乱写；测试数据前缀保留现约定。  
- 审计：来客 ID、直客 ID、账户 ID、授信额度的改前改后。  
- 企业微信登录失败时不可静默落到本地账号冒用组织。

## 13. 迁移原则

- 旧客户/主体/账户只读迁移，不合并双树历史客户（54 对重名留给清洗任务）。  
- 开户申请 `shop_no` 为 19 位数字的，回填为来客 ID。  
- 角色重建，旧账号映射企业微信。  
- 机器人改为写新单据表，群配置后期单独重构。

## 14. 里程碑（只排序，不排期）

1. 主数据加字段 + 开户申请改选择 + 来客校验 + 自有端口落账户。  
2. 四角色工作台 + 企业微信工作流主链。  
3. 字段模板后台。  
4. 财务闭环（到账、对账、授信真审）。  
5. 机器人接入与现金配置治理。
