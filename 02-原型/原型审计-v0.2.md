# 原型审计与冲突清单 v0.2

## 审计范围

- 表面：用户提供的 v0.1 商务工作台与字段模板截图。
- 流程：商务工作台 → 开户申请 → 开户媒介批量处理 → 字段模板/反馈。
- 证据：本轮生产只读角色/菜单聚合、本地脱敏数据库副本、现有 PRD 与反编译规则。
- 截图：`qa/reference-workbench.png`、`qa/reference-field-template.png`、`qa/implementation-desktop.png`、`qa/implementation-mobile.png`。

## 编号步骤与健康度

1. **商务工作台 — 已重构，健康**：真实角色与数据范围进入页头；生产聚合和演示待办分标；商务看不到管理员配置。
2. **开户申请 — 已重构，健康**：媒体产品与供货渠道分轴；客户/主体/供应商按 ID 选择；支持多账户需求与条件资质。
3. **开户媒介处理 — 已重构，健康**：支持批量粘贴、逐账户校验、部分成功、待补录和来客纠错闭环。
4. **字段与表单规则 — 已重构，健康**：维度从四列开关扩展为对象、产品、阶段、渠道、角色、来源、条件、校验、纠错和版本。
5. **字段调整反馈 — 已新增，健康**：点击全局或清单内 `＋` 后直接在页面展开填写，提交后立即追加展示并可导出 JSON，不会直接改变生产。
6. **移动与键盘使用 — 已修复，基本健康**：窄屏导航改为横向快捷条；弹窗具备焦点、Esc 和 Tab 循环；完整读屏仍需专门测试。
7. **全局自由编辑 — 已新增，健康**：每页可直接修改文字与示例值，字段/行/卡片可增删；保存按页面变体持久化，取消与恢复默认范围明确。

## 最高影响冲突

| 优先级 | 旧原型问题 | v0.2 处理 |
|---|---|---|
| P0 | 6 个抽象角色只换按钮样式，菜单与数据不变 | 导入 15 个启用角色事实；人工角色模拟会改变首页与最小权限导航；RPA 单列 |
| P0 | “老板”合并了总经理和董事长 | 拆为总经理（本部门）与董事长（全局） |
| P0 | 媒体产品与“本地推/非本地推”及供应商混用 | 拆为媒体产品字典码 × AGENT/NOAGENT 供货渠道 |
| P0 | “直客”同时表示合作关系与平台 ID | 使用“直接合作客户/渠道客户”与“巨量直客 ID”两个名称 |
| P0 | 来客 ID 默认来源写“店铺”，实际多数 `shop_no` 是内部串 | 设计独立 `laike_id`；保留 `shop_no` |
| P0 | 纵横 ID 出现在商务申请且设空来源硬必填 | 移到开户回复，仅巨量条件显示，允许待媒介补 |
| P0 | 一张开户单只演示一个账户 | 增加账户需求明细和批量结果；支持部分成功 |
| P0 | 模板“保存即生效” | 改为草稿 → 校验 → 预览 → 发布版本；在途单冻结旧版本 |
| P0 | “同步状态不为 30”一律算失败 | AGENT 平台同步与 NOAGENT 无需 API 分开 |
| P0 | 财务 KPI 是无来源 mock | 改用 142 笔待确认现金、206 张未完成对账等真实聚合 |
| P1 | 企业微信组织被写成已经接入 | 标记为目标态；现网未形成可验证路由 |
| P1 | 角色 = 部门 = 数据范围 | 拆成功能权、组织权、协作权，覆盖多层组织和共享关系 |

## 可见的可访问性风险与处理

- 旧版角色胶囊数量多且无权限语义；改为有标签的角色选择器和禁用导航。
- 状态不再只靠颜色，同时显示“待补、失败、无需 API、生产事实、演示待办”等文字。
- 宽表放入横向滚动容器；390px 下表单改为单列。
- 弹窗具备 `role=dialog`、`aria-modal`、关闭按钮、Esc、焦点恢复和 Tab 循环。
- 自由编辑工具栏可键盘访问，`Ctrl+S` 保存；增删按钮具有“移除字段/表格行/卡片”等可读名称。

## 证据限制

- 线上站点进入登录页后没有可复用的业务账号会话，因此没有逐页操作线上 UI；角色、菜单与业务聚合来自生产库只读查询，表单行为来自本地部署包、反编译代码和脱敏副本。
- 截图不能证明完整 WCAG 合规；上线前仍需真实读屏、200% 缩放和企微内嵌浏览器测试。
- 个性化任务数仍是演示数据，因为现网没有重构后的通用工作流任务表。
