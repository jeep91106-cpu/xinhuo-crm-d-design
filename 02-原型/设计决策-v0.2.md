## 边界

- 生产服务器、生产数据库、线上项目全程只读；原型代码只改本地设计仓库。
- 页面中的客户、主体、账户和供应商均为脱敏示例；生产数据只展示聚合数。

## 已解决的核心冲突

1. **角色不是顶部皮肤切换**：角色切换现在会改变首页与导航权限；总经理、董事长分开，RPA 单列为服务身份。
2. **角色不等于部门**：数据范围拆成功能权、组织权和协作权；支持本人、本部门、部门及以下、自定义、全部、共享给我、共享给部门和流程经办。
3. **媒体产品不等于供货渠道**：媒体产品保存稳定字典码；供货渠道独立为 AGENT / NOAGENT；供应商再按两者过滤。
4. **“直客”不再双义**：合作关系叫“直接客户/渠道客户”；平台编号统一叫“巨量直客 ID”；主体名称只注明业务称谓。
5. **来客 ID 不复用 `shop_no`**：8,244 个店铺中只有 32 个 `shop_no` 是 19 位纯数字；原型改为独立 `laike_id`，内部编号继续保留。
6. **开户不是单账户表单**：开户申请增加账户需求明细，处理页支持批量粘贴、逐行校验、部分成功与待补录。
7. **新字段不假装已经存在**：直客 ID、纵横 ID、社会信用代码、主体/供应商银行资料等明确标为新字段或待补录来源。
8. **返点不直接取客户当前值**：前返改为合同/报价规则生成的交易快照；偏离默认需说明。
9. **字段模板不是改完即用**：拆成字段字典与表单规则，并增加冲突校验、预览、版本发布、只影响新单和回滚前提。
10. **反馈就在页面内完成**：点击 `＋` 后在字段调整清单内展开填写，提交后立即追加展示；不再用弹窗打断上下文。
11. **整页自由编辑采用视觉补丁层**：不保存整页 HTML，只按页面/产品视图保存文字、字段值、删除项和结构化新增项；切页、刷新和动态筛选后仍可复用。
12. **所有增删都可撤销**：字段、表格行、卡片、任务与规则均有 `－`，对应区域有 `＋`；保存、取消、恢复默认互不混用。
13. **生产事实与演示任务分开**：所有真实数字标“生产聚合事实”；个性化待办标“演示待办”。

## 尚待业务确认

- 本地推在什么条件下可以复用来客资质，从而不再要求社会信用代码、银行与住所。
- 一个主体的巨量直客 ID 唯一范围：每个供应商/端口唯一，还是同端口也允许多个。
- 纵横 ID 在哪些巨量产品、组织关系或账户类型下必须填写；历史数据如何补齐。
- 新组织工作流是否直接对接企业微信，还是先以 CRM 组织为主、企业微信仅做登录与通知。

## 生产实施前置

原型通过不代表可以上线。正式实施至少需要数据库迁移、接口契约、旧树合并映射、历史缺失策略、批量数据回放、权限最小化评审、模板/流程版本与回滚，以及生产外的完整验收环境。
