# 薪火 CRM 重构 · 需求一页纸

**产品**：广告流量代理公司内部 CRM（现网 RuoYi-Vue，2026-07 上线）  
**上游**：巨量引擎为主，腾讯 / 快手保留不删；外转代理商路径收缩但不停  
**优先级**：商务 + 开户/充值媒介 > 财务 > 老板  
**版本**：v1.0 · 2026-09-15 · 已与用户对齐，可作为其他 Agent 的唯一需求入口

---

## 一句话

不推翻现有业务和四层主数据，把「抖音事业部 / 其他媒体」合成一套流程；商务一次填对、下游可选可改可回填；每人一个按企业微信组织流转的工作台；字段和工作流可在后台配置。

## 用户原话（四条痛点）

1. 填写字段过多  
2. 填完后流转中不能回填、不能选择  
3. 没有工作台  
4. 没有后台配置模板  

## 已确认、不得改的业务骨架

| 项 | 决定 |
|---|---|
| 对象层级 | **客户 → 主体 → 店铺 → 广告账户** 四层不动。客户是合作/付款方；直客只是 ID 字段，不是新实体。 |
| 业务类型 | 一个主体可同时做本地推 / 巨量 AD / 腾讯 / 快手，**不加互斥**。类型记在**广告账户** `type` 上，不升到主体。 |
| 直客 ID | **一个主体可以有多个直客 ID**。不落主体单列；落在开户申请 → 广告账户，主体页汇总。 |
| 来客 | 仅抖音本地推有。商务填来客名称 / 来客 ID，流转到开户媒介；媒介不对可改（须留痕、回推商务）。 |
| 账户层 | 指第四层 **广告账户**（16 位广告账户 ID + 纵横 ID），不是客户钱包、不是登录账号。 |
| 模块合并 | 「抖音事业部」与「其他媒体」合并为一套菜单与流程；差别是供应商自有端口（API）还是外转代理商（记账）。 |
| 归属 | 不设计静态「归属渠道 / 负责商务 / 媒介」字段。经办人由 **企业微信登录 + 后台工作流** 按组织配置：主流程 **商务 → 开户媒介 → 充值媒介 → 财务**，中间部门与颗粒度可配（如沈阳走沈阳组织）。 |
| 角色权限 | 现网账号可废弃重建，不以旧 `sys_role` 为基线。 |
| 机器人 / 现金 | 现状混乱，列入重构，不在旧系统上补丁。 |

## 商务填写（按业务类型分支）

**若本地推**

- 直客名称、直客 ID  
- 来客名称、来客 ID（19 位数字，必填）  

**否则（巨量 AD / 腾讯等）**

- 行业  
- 公司名称、社会信用代码  
- 开户银行名称、开户银行账号  
- 住所、联系人、电话  

以上挂在主体资质或当次开户申请上，下游**选择已有记录**，不再手抄。

## 开户媒介填写

**广告账户**：账户名称、账户 ID、纵横 ID、供应商、账户所属（商务个人 / 渠道公司）  

**供应商主数据（每家代理商填一次，账户只选）**：代理商名称、代理商 ID、开户行号码、开户行地址（代理商收款户，我们付款用）

## 主流程（保持原逻辑，只补回填与配置）

```
建档客户 → 建/选主体（资质一次录入）→ 本地推则建/选店铺(来客)
  → 开户申请（选客户/主体/店铺/供应商，按模板出字段）
    → 开户媒介处理（回填账户 ID / 纵横 ID；可改正来客 ID）
      → 充值媒介（返点默认带出；自有端口调 API，外转只记账）
        → 财务（现金到账、对账、授信/退现）
```

资金三种：客户现金备款、客户授信垫款、广告账户货币。现网 96% 充值走授信。消耗：自有端口 API 拉取，外转导入。

## 四个角色工作台（必须做）

| 角色 | 工作台只放 |
|---|---|
| 商务 | 待提交 / 被驳回的开户与资金申请；我的客户与主体；流程进度；来客/资质被媒介改过的通知 |
| 开户媒介 | 待处理开户单（按组织队列）；缺账户 ID / 缺资质；可改来客并留痕 |
| 充值媒介 | 待确认充值；自有端口同步失败；供应商余额预警；外转待线下划款 |
| 财务 | 待确认现金到账；待对账；授信/退现待审；逾期授信 |
| 老板 | 消耗 / 授信占用 / 开户时效 / 各组织积压（只读） |

## 后台必须可配

1. **字段模板**：按媒体产品（本地推 / 巨量 AD / 腾讯 / 快手）× 阶段（商务申请 / 开户回复 / 充值）配置显示、必填、默认、是否可改。  
2. **工作流**：节点、组织范围、候选人规则、超时；企业微信身份驱动。  
3. 停用事业部树只隐藏不删除。

## 本轮不做 / 明确非目标

- 不重做四层对象关系，不加「业务类型互斥」  
- 不删腾讯 K4 / 快手 / 外转路径  
- 不以现网 12 个零登录商务账号为权限设计依据  
- 不把生产 dump、客户明细、密钥写入本仓库  

## 验收（商务 + 媒介优先）

1. 商务开本地推：只填直客 + 来客两组；主体/供应商是选择不是手抄；提交后开户媒介待办出现同一条，字段只读带回。  
2. 商务开非本地推：出资质七项 + 行业；本地推字段不出现。  
3. 媒介改来客 ID：必填原因，改前改后可查，商务工作台收到通知。  
4. 充值单前返/后返默认来自客户或账户，可改但不必每笔从零填。  
5. 沈阳账号发起的单，只进入沈阳配置的开户/充值队列。  
6. 管理员能改字段模板和工作流节点，无需发版。

## 仍待确认（不阻塞一页纸）

一个主体多个直客 ID 的产生规则：是否「每个供应商/端口一个」？若同一端口也会多个，账户上挂直客 ID 仍然够用。
